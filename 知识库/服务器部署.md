### 一个项目在公司从创建到部署的流程

1. **部署岗位划分（将项目部署至服务器分为几类场景）：**
   - 公司专职运维 / DevOps：负责公司服务器、云集群、CI/CD 持续发布；
   - 小型公司无专职运维：后端开发自行打包部署；
   - 实施 / 交付工程师：核心工作是**私有化部署**，远程或上门把软件部署到客户自有服务器；
   - 大厂基础架构 / 平台团队：维护统一云平台，提供标准化发布能力。

2. **私有化部署（部署到客户服务器）关键要点**

   > 部署到客户服务器 ≠ 交付源代码：

   - 常规方案：仅交付编译后的运行包，不提供源码；

   - 源码交付属于单独商业条款，需要额外签约、加价；

   - 注意：PHP、Python、Node 等解释型项目，若直接上传源码运行，客户可直接获取代码，存在风险。

     运维边界依靠合同约定：通用规则是客户负责服务器底层系统，厂商负责应用软件 Bug 与版本更新。

3. **两种核心部署模式区分**

   - **SaaS 托管部署****：程序部署在**公司自有 / 公司租用云服务器**（阿里云、腾讯云等），客户通过网络（公网）访问使用；厂商全权负责服务器运维、升级、数据托管；

   - **私有化部署**：程序部署在**客户服务器 / 客户云环境**。

4. **结合业务形态（ToC / ToB）**

   - **ToC（面向普通个人用户）**：主流为 **SaaS 云端托管模式**。私有化部署极其罕见，普通消费者没有服务器与运维能力，商业模式无法支撑单独部署成本；

   - **ToB（面向企业客户）**：两种模式并存：既可以选择 SaaS 租用，也可以根据合规、数据安全需求选择私有化部署。

**极简记忆版**

- 放公司服务器供外部使用 → SaaS；ToC 主流方案；运维 / DevOps 负责长期维护

- 放到客户服务器上运行 → 私有化部署；ToB 常见，一般由实施工程师交付实施；**部署位置不代表一定会交付源码，以合同为准**
