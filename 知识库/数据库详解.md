## 向量数据库

1. 轻量向量索引库（FAISS）：**仅存向量**，元数据需要外部数据库配套；
2. 生产级向量数据库（Milvus/Qdrant/Chroma）：**向量 + 结构化元数据一起存储**，原生支持混合过滤检索；
   - Milvus/Qdrant：**原生为向量检索设计的独立服务**，专门解决亿级向量、高并发检索；
   - FAISS：**纯向量检索库**，只存浮点数组，无完整数据库能力；
3. 有些传统的数据库会带有向量存储的拓展，比如**PostgreSQL**
   - PostgreSQL 本身原生不支持向量，靠开源扩展 **pgvector** 实现全套向量能力，本质是给 PG 新增三类能力：
     - **全新数据类型**：`vector(N)`、`halfvec(N)`、稀疏向量类型，专门存储浮点嵌入数组；
     - **向量计算运算符**：余弦距离 `<=>`、L2 距离 `<->`、内积 `<#>`，C 底层高速计算相似度；
     - **向量专用索引**：HNSW、IVFFlat，实现百万级向量近似最近邻检索（ANN）。

4. 存储逻辑（一张表同时存向量 + 业务元数据，完美解决你之前的误区）

## 在企业具体场景中

| 存储类型   | Docker 开发环境     | 企业生产环境                |
| ---------- | ------------------- | --------------------------- |
| PostgreSQL | Docker Volume       | 云 RDS（推荐）或物理服务器  |
| Redis      | 内存（重启丢失）    | 云 Redis 服务（开启持久化） |
| 对象存储   | MinIO Docker Volume | 云对象存储（OSS/S3，推荐）  |

核心变化 ：

1. 从容器化到服务化 ：数据库不再作为容器部署，而是使用云服务商提供的托管服务或自建高可用集群
2. 从本地存储到分布式存储 ：数据存储在专业的存储设备或云存储服务中
3. 从单实例到高可用 ：部署主从复制、读写分离、自动故障转移
4. 从手动管理到自动化 ：自动备份、自动扩容、性能监控
  这种架构变化的目的是 保证数据安全、系统稳定、业务连续性 ，这是企业级应用的核心要求。

> 小型企业现在越来越多地使用云服务器 ，原因如下：
>
> - 成本优势：比直接部署自己的物理服务器便宜
>
> - 灵活性：可以咋高峰期扩容，低谷期缩容
>
> - 技术门槛低：本地物理服务器需要专业人员部署与维护
