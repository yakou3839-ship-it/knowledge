# WebSocket 是什么

## 一句话总结

**WebSocket 是一种在单个 TCP 连接上实现「双向实时通信」的网络协议**，浏览器和服务器一旦建立连接，双方可以随时互相发消息，不用像 HTTP 那样每次都新建请求。

## 先对比 HTTP，看懂痛点

### HTTP（普通网页接口）

- 模型：**一问一答，单向**

- 流程：客户端发请求 → 服务器响应，连接随即断开

- 缺点：服务器不能主动推送数据给浏览器

  如果要做实时消息（聊天、行情），只能轮询（不停发请求），浪费带宽、延迟高。

### WebSocket

- 模型：**持久长连接，双向通信（全双工）**
- 流程：
  1. 先用一次 HTTP 请求完成**握手**
  2. 握手成功后，协议升级为 WebSocket，TCP 连接持续保持
  3. 客户端 ↔ 服务器**随时互相发送消息**

握手示意图：

```
客户端：HTTP 请求，携带 Upgrade: websocket
服务器：响应 101 Switching Protocols
↓
协议切换完成，正式进入 WebSocket 长连接
```

## 核心特点

1. **全双工**：两端可以同时收发数据
2. **长连接**：连接建立后不断开，直到主动关闭 / 网络中断
3. **头部开销极小**：不像 HTTP 每次带大量请求头，消息帧很轻，适合高频通信
4. **同源策略可控**，浏览器原生支持 `WebSocket` API

## 典型使用场景

- 即时聊天（IM、在线客服）
- 股票 / 加密货币实时行情、数据看板
- 在线游戏、多人协同文档
- 设备状态推送（物联网、监控告警）
- 直播间弹幕、实时通知

## 简单浏览器原生示例（前端）

javascript

```
// 建立连接
const ws = new WebSocket("ws://127.0.0.1:8080");

// 连接打开
ws.onopen = () => {
  ws.send("Hello Server");
};

// 接收服务端消息
ws.onmessage = (e) => {
  console.log("收到：", e.data);
};

// 连接关闭
ws.onclose = () => console.log("连接断开");

// 错误监听
ws.onerror = (err) => console.error(err);
```

## 地址协议区分

- `ws://`：非加密 WebSocket（类似 http://）
- `wss://`：加密 WebSocket（类似 https://，生产环境优先使用）

## 和 SSE 的区别（容易混淆）

- **WebSocket**：双向，客户端、服务端互发消息
- **SSE（Server-Sent Events）**：单向，只能服务器发、浏览器收，底层仍是 HTTP

## 常见误区

1. ❌ WebSocket ≠ HTTP

   ✅ 只是握手阶段借用 HTTP，通信阶段是独立协议

2. ❌ 永远不会断连

   ✅ 网络波动、超时、代理、防火墙都会切断，业务必须实现断线重连
