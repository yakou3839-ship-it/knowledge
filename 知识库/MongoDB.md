# MongoDB 完整入门：是什么、用途、学习路线
## 一、MongoDB 是什么
### 1. 基础定义
MongoDB 是一款**开源、跨平台的 NoSQL（非关系型）文档数据库**，由 C++ 开发，区别于 MySQL、Oracle 这类传统关系数据库。
- 关系库：表(table)、行(row)、字段(column)，固定表结构，用 SQL 查询
- MongoDB：集合(collection)、文档(document)、字段(key)，**无固定结构**，用类 JSON 的 BSON 存储数据

### 2. 核心概念对照（MySQL ↔ MongoDB）
| MySQL 关系数据库 | MongoDB 文档数据库 | 说明 |
| ---- | ---- | ---- |
| 数据库 Database | 数据库 Database | 顶层数据容器 |
| 表 Table | 集合 Collection | 一组同类数据 |
| 行 Row | 文档 Document | 单条数据，BSON 格式 |
| 列 Column | 键 Key | 数据字段 |
| 主键 id | _id | 文档唯一标识，自动生成 |
| 外键关联 | 内嵌文档 / 引用文档 | 替代多表联查 |

### 3. BSON 是什么
Binary JSON，二进制JSON：
- 兼容 JSON 所有格式（对象、数组、字符串）
- 额外支持日期、数字、布尔、二进制、ObjectId、小数等数据库专用类型
示例一条文档：
```json
{
  "_id": ObjectId("60xxxxxx"),
  "username": "zhangsan",
  "age": 20,
  "tags": ["学生","编程"],
  "info": {"school":"XX大学"}
}
```

## 二、MongoDB 有什么用（适用场景+优缺点）
### 1. 优势（为什么选MongoDB）
1. **灵活 schema**
   不用提前建表、定义字段，业务迭代时新增字段无需改表结构，适合快速迭代项目（小程序、后台管理、APP）。
2. **高并发读写**
   内置内存映射机制，热点数据放内存，查询速度快，适合海量用户、高频接口。
3. **天然支持海量数据分片**
   原生分片集群，轻松水平扩容，支撑千万/亿级数据量。
4. **复杂数据天然存储**
   数组、嵌套对象直接存文档，不用拆多张表，减少联表查询。
5. **高可用**
   副本集自动主从切换，宕机自动选举新主库，保障数据不丢失。

### 2. 典型业务场景
1. **互联网APP/小程序用户数据**：用户信息、标签、动态、收藏、购物车
2. **内容平台**：文章、评论、商品详情（字段多变，商品参数不统一）
3. **实时日志、埋点数据**：用户行为、操作日志，写入量大、结构不统一
4. **物联网IoT**：设备上报数据，设备字段差异大
5. **大数据分析临时存储**：爬虫抓取数据、半结构化数据
6. **中台/低代码平台**：动态表单、自定义字段业务

### 3. 不适合的场景
1. 强事务、多表复杂事务（金融转账、账务核心，优先 MySQL）
2. 多表深度联查、大量聚合统计（复杂报表优先关系库）

## 三、完整学习路线（零基础可直接照做）
### 阶段1：环境搭建（本地+可视化工具）
#### 1. 安装 MongoDB✅️
- Windows / Mac / Linux 都有安装包，推荐社区免费版
- 两种使用方式：
  1）本地安装 MongoDB Server + shell（mongosh）命令行操作✅️
  2）MongoDB Atlas（免费云数据库，不用本地安装，新手首选，开箱即用）❌️

#### 2. 可视化管理工具（必装，降低学习难度）✅️
- MongoDB Compass：官方免费可视化，查看集合、执行查询、导入导出✅️（新版默认装）
- NoSQLBooster：功能更强，智能提示、SQL转Mongo语法❌️
- 也可以用navicat之类的可视化工具

#### 3.启动服务✅️

- 先将bin文件路径添加到环境变量中

- 配置数据库位置

  > 任何位置都可以
  >
  > 新建data/db、data/log（这个咱们没用到）文件夹
  >
  > 这里的db代表的就是数据库

- cmd启动数据库，等待连接

  ```bash
  #命令范式
  mongod --dbpath db路径 --port 端口号      #默认不夹--port是直接用27018
  ```

- cmd连接数据库启动服务

  - 注意：新版mongodb需要手动下载mongosh：https://www.mongodb.com/try/download/shell

  - 打开一个新的cmd

    ```bash
    #自动连接服务
    #命令范式
    mongosh --port 端口号         #默认不夹--port是直接用27018 
    ```

- 问题：

  > 1. 无论用那个db位置启动只要不加端口号，都是默认启动同一个
  > 2. 要想启动指定文件夹，需要在启动服务的时候指定不同的端口号

#### 4. 快速验证安装✅️

打开 `mongosh` 执行：
```js
// 创建数据库并插入一条数据
use test_db
db.user.insertOne({name:"test",age:18})
// 查询数据
db.user.find()
```





### 阶段2：基础语法（核心CRUD，重中之重）❌️（先过）

1. 数据库操作：`use` 创建/切换库、`show dbs`、`dropDatabase()`
2. 集合操作：创建集合、删除集合、`show collections`
3. 新增文档
   - `insertOne()` 单条插入
   - `insertMany()` 批量插入
4. 查询文档（最常用）
   - `find()` / `findOne()` 基础查询
   - 条件匹配：`$gt $lt $eq $ne` 大于、小于、不等于
   - 数组匹配：`$in $all`
   - 模糊匹配正则、分页 `skip() limit()`、排序 `sort()`、投影只返回指定字段
5. 更新文档
   - `updateOne()` / `updateMany()`
   - 修改操作符：`$set $inc $push $pull`（新增字段、自增、数组增删元素）
6. 删除文档
   - `deleteOne()` / `deleteMany()`

### 阶段3：进阶核心能力
1. **索引**
   单字段索引、复合索引、唯一索引、数组索引；索引优化，避免全表扫描（大数据必学）
2. **文档关系设计**
   - 内嵌文档：一对一、一对少（简单，不用联查）
   - 引用文档：一对多、多对多（类似外键，适合数据量大场景）
3. **聚合管道 Aggregate**
   `aggregate()` 替代SQL group by、join、子查询
   常用管道：`$match $group $sort $limit $lookup $project`
4. 事务：多文档事务（4.0+版本支持）
5. 数据导入导出：mongoimport / mongoexport

### 阶段4：运维与集群（后端开发进阶）
1. 副本集 Replica Set：主从备份、故障自动切换
2. 分片集群 Sharding：海量数据水平分库分表
3. 权限管理：创建账号、分配读写权限
4. 备份恢复、性能监控、慢查询优化

### 阶段5：编程语言驱动（对接业务代码）
学会原生命令后，结合你使用的编程语言实操：
- Python：pymongo
- Java：MongoDB Java Driver / Spring Data MongoDB
- Node.js：mongoose（最流行ODM框架）
- Go、C#、PHP 都有官方驱动

以 Node.js Mongoose 举例：ODM 框架，给文档增加模型约束、校验、中间件，企业项目标准用法。

## 五、新手学习顺序建议
1. 搭建 Atlas 云数据库，不用本地配置环境，快速上手CRUD
2. 熟练增删改查、条件查询、分页排序
3. 学习索引，理解如何提升查询速度
4. 学习聚合管道处理统计需求
5. 学习数据模型设计（内嵌 vs 引用）
6. 对应编程语言驱动写接口实战
7. 有余力再学副本集、分片、运维优化

## 六、常见误区提醒
1. MongoDB 不是完全不用设计结构，只是灵活；复杂业务仍要提前规划模型
2. 不要滥用内嵌文档，超大内嵌数组会导致查询、更新性能暴跌
3. 不建索引等于慢查询，生产环境核心查询字段必须建索引
4. 事务能力弱，核心金融业务不建议只用MongoDB，可 MySQL + MongoDB 搭配使用
